Checklist de Infraestrutura e Rede

Itens conferidos 0 de 0
Pense na rede da clínica como uma rua: o equipamento VMI e o computador que recebe as imagens são duas casas. Para uma mandar imagem para a outra, cada uma precisa de um número de casa que não muda (IP fixo), as duas precisam morar na mesma rua (os três primeiros números do IP iguais) e a porta precisa estar destrancada (porta 104). Fora isso, o servidor precisa de internet liberada para mandar tudo para a nuvem. Todo o checklist gira em volta dessas três coisas.

3. Cabeamento e conexão

Antes da instalação, verifique se os cabos de conexão do equipamento e do computador estão conectados.

Cabo de rede ligado no computador e no equipamento É aquele cabo azul ou cinza, com ponta quadrada, que faz “clique” ao encaixar. Os dois precisam estar ligados por cabo. Wi-Fi não é adequado para enviar imagens, pois oscila e apresenta perda de velocidade, o que pode causar erros no envio do exame.
Velocidade da internet medida A imagem chega ao computador pela rede interna, mas o envio à nuvem e o acesso ao laudo dependem da internet. É preciso que a conexão tenha mais de 50 Mbps de upload. Abra o Speedtest e clique em iniciar.
Abrir speedtest.net
ConfortávelUpload de 50 Mbps ou mais e latência inferior a 50 ms.
O número que mais importa é o de upload (subida): é por ele que o exame sai da clínica.

4. Acesso remoto (AnyDesk)

É o programa que deixa o suporte ver a tela do computador de longe. Só isso: abrir o programa e anotar o número que aparece.

Como instalar, passo a passo
1 Abra o navegador e vá em anydesk.com/pt → botão Baixar agora. O arquivo baixado chama AnyDesk.exe (no Linux, o pacote .deb).
2 Dê dois cliques no arquivo. Se o Windows perguntar “Deseja permitir que este aplicativo faça alterações?”, responda Sim. O programa já abre pronto para usar, mesmo sem instalar.
3 Clique em Instalar o AnyDesk neste dispositivo e confirme. Instalado, ele volta sozinho depois de reiniciar o computador — sem instalar, alguém precisa abrir o programa toda vez.
4 Na tela principal, anote o número de 9 dígitos em “Este dispositivo” e escreva no campo abaixo. É esse número que o suporte pede.
5 Opcional, mas recomendado: Configurações → Segurança → Acesso não supervisionado e defina uma senha. Assim o suporte entra fora do horário sem depender de alguém clicar em “Aceitar”.

2

Liberar a porta 104 no firewall

sudo ufw status

Se aparecer Status: active, a porta 104 precisa estar na lista como ALLOW. Se não estiver, libere:

sudo ufw allow 104/tcp
sudo ufw reload

Em distribuições com firewalld (RHEL, Rocky, Fedora), use sudo firewall-cmd --list-all.

⚠︎ Os dois IPs precisam começar com os mesmos três números (ex.: 192.168.1.50 e 192.168.1.10). Se começarem diferente, estão em “ruas” diferentes e não vão se enxergar.
Os dois se enxergam na rede
Como validarCompare os três primeiros números dos dois IPs. Depois, no computador: ping IP-do-equipamento.
Está certo seOs três primeiros números forem iguais (ex.: 192.168.1.50 e 192.168.1.10) e o ping responder. Se não responder, a TI precisa liberar o caminho entre as duas redes (para a TI: mesma VLAN, sem NAT).
Se estiver erradoPeça à TI para ligar os dois na mesma rede (mesmo switch/VLAN) ou liberar a rota entre elas.

BLOCO 3 · MÁQUINA VIRTUAL

Passo a passo

Escolha como o servidor Audo PACS vai rodar nesta clínica. As etapas extras deste bloco só existem para o cenário de máquina virtual — nos outros dois, o Bloco 2 já cobre tudo.

Servidor físico rodando Windows

Sem máquina virtual envolvida. O sistema operacional, a rede e o firewall desse computador já foram conferidos nos itens 6 a 9, no Bloco 2 — não há etapa extra aqui.

Servidor físico rodando Linux

Sem máquina virtual envolvida. O sistema operacional, a rede e o firewall (ufw) desse computador já foram conferidos nos itens 6 a 9, no Bloco 2 — não há etapa extra aqui.

Máquina virtual (Windows por baixo, Linux dentro)

A máquina virtual só recebe imagem se ela aparecer na rede da clínica como se fosse um computador de verdade. Isso é o Modo Bridge.

1

Colocar a placa da VM em Modo Bridge (Ponte)

  • Hyper-V (padrão da instalação VMI): Gerenciador do Hyper-V → Gerenciador de Comutador Virtual → criar ou usar um comutador do tipo Externo, apontando para a placa com cabo. Depois: Configurações da VM → Adaptador de Rede → escolher esse comutador.
  • VirtualBox: com a VM desligada → Configurações → Rede → “Conectado a:” → Placa em Modo Bridge.
  • VMware: a opção equivale a Bridged.

2

Dentro da VM: endereço fixo e porta 104

Ligue a VM e, dentro do Linux, repita os dois passos do Cenário 2: endereço em Manual e porta 104 liberada. O endereço tem que ser da mesma faixa da clínica (ex.: 192.168.1.x). Se aparecer algo como 10.0.2.x, a placa ainda está em NAT — volte ao passo 1.

Ilustração · como saber se está em Bridge
Bridge ✓ — endereço da clínica
vmi@vm:~$ ip a | grep inet

NAT ✕ — endereço escondido
vmi@vm:~$ ip a | grep inet
    inet 10.0.2.15/24 … enp0s3

Rode o comando dentro da VM. Endereço na faixa da clínica (ex.: 192.168.1.x) = Bridge funcionando. Começou com 10.0.2. = ainda em NAT.

3

O Windows por baixo também precisa liberar

O firewall e o antivírus do Windows podem barrar o tráfego antes de ele chegar à VM. Repita o passo 3 do Cenário 1 nele, e configure a VM para iniciar junto com o Windows — assim ninguém precisa ligar a VM na mão depois de uma queda de energia.
